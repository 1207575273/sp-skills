# 配图生成规范

代码生成配图:HTML 模板 + 浏览器截图。零 API 成本、零版权风险、风格完全可控。

## 尺寸规格

| 图 | 尺寸 | 说明 |
| --- | --- | --- |
| 封面 cover.png | 1800 x 766 | 公众号 2.35:1 的 2 倍,发布时零裁损;文件名固定 cover.png(发布环节按此名取封面) |
| 开篇导览图 fig0-overview.png | 宽 1200,高随内容 | 每篇标配,正文第一个元素。深色品牌横幅风格(与封面同色系但内容不同):本文地图 + 分层/主线 + 一句"读完带走什么"。开宗明义,不与标题文案重复 |
| 正文插图 figN-语义名.png | 宽 1200,高随内容 | 模板 body 定宽 1200,高度由内容撑开 |

## 设计约束

- 全文所有图统一一套色系(实战例:深蓝 #0E1230 封面 + 浅底 #FAFBFF 插图 + 靛蓝 #4F46E5 强调色)
- 字体统一 `"Microsoft YaHei","PingFang SC",sans-serif`
- 封面:大标题不超过两行,副题一行,留白充足;文字距边不小于 90px
- 插图:标题 + 一句副题 + 卡片化内容;信息密度宁少勿挤,文字溢出是最常见翻车点
- 不用 emoji;箭头用 `->`

## 目录与跨篇一致性

- **按篇建子目录** `articles/assets/<YYYYMMDD-slug>/`,绝不与其他篇共用目录(同名 cover.png/figN 会互相覆盖,已实战踩过)
- **色系跨篇沿用同一套**,这是账号的视觉资产(当前:深蓝 #0E1230 封面底 + 浅底 #FAFBFF 插图 + 靛蓝 #4F46E5 强调);新篇直接从上一篇的模板复制起步,历史子目录里的 HTML 都是现成参照

## 制作流程

1. 每张图写一个独立 HTML,放本篇子目录,命名与最终 PNG 同名(cover.html -> cover.png)
2. 模板骨架直接抄 `templates/cover-template.html`(封面)和 `templates/figure-template.html`(插图)改内容
3. 批量截图:

```bash
node .claude/skills/wechat-post/scripts/shoot-figures.mjs "articles/assets/<YYYYMMDD-slug>"
```

脚本对每个 HTML 的 body 做元素级截图(尺寸精确,不带视口空白),输出同名 PNG 并打印尺寸。

4. 验收:核对打印的尺寸(封面必须 1800x766);逐张打开目检文字溢出与错别字

## 模板要点(为什么这样写)

- `body` 定死宽度(封面连高度也定死),截图边界即内容边界
- 所有样式内联或 `<style>` 均可(截图产物是 PNG,不受公众号粘贴清洗影响)
- 封面文案与文章标题呼应但不必逐字相同,取更短的口号化表达
