# 公众号写作规范

首篇实战验证过的写法,按此执行。

## 前置:资料核实

- 动笔前联网搜索选题的最新事实(发布时间、人物、数据、时间线)
- 多来源交叉确认;只有单一来源的夸张说法(天价收购、惊人数字)一律不采用
- 涉及具体项目/公司的历史,以官方或多家独立媒体一致的版本为准
- **用户口述提纲里的产品/项目名先联网校正再落笔**(实战例:langchina -> LangChain,deppagent -> DeepAgents,deepseekharess -> DeepSeek Harness),正文使用官方拼写
- **优先找 7 天内的时事爆点当开头钩子**(实战例:首篇用 OpenClaw 律师函三连改名,次篇用 DeepSeek Harness 两天 95K star)。越新越有共鸣,搜索时主动查"选题关键词 + 近一周大事"

## 结构模板

0. **开篇导览图**:正文第一个元素(标题之后、钩子之前)固定放一张 `fig0-overview.png`——开宗明义的"本文地图",列出全文主线/分层/读者收获,深色品牌横幅风格。让读者第一眼知道这篇讲什么、读完带走什么
1. **钩子开头**:具体场景 + 悬念,不超过 3 段(实战例:深夜律师函 + 三天两次改名)
2. **一条主线**:把素材压成一个贯穿性叙事(实战例:70 年历史压成"三次选择"),不做流水账
3. **分节推进**:每节一个二级标题,标题本身有信息量
4. **收束**:回扣开头,把宏大叙事落到读者自身的一个问题上
5. **结尾**:一句"关注我" + 下篇预告(预告与当前系列相关,形成连载钩子)。**上一篇的预告要兑现或呼应**:写新篇前回看上篇结尾承诺了什么,能接上就接上,接不上也在选题上保持系列感(实战:首篇预告"自动化流水线",次篇预告"最小可用可观测",逐篇成链)

## 规格

- 1000-1500 字,段落 3-5 行,重要断言单独成段加粗(全文 2-4 处金句)
- 中文与英文/数字之间留空格;不用 emoji 和装饰符号
- 图片占位:在需要配图处写 `![图片描述](assets/figN-语义名.png)`,通常 3 张:
  - 主线总览图(第一节前)
  - 核心对比/机制图(文章中段)
  - 全景/格局图(结尾前)

## 标题

产出 5 个备选,覆盖这些套路(每个至少占一路):

- 数字 + 反差:"AI 这 70 年,其实只做对了三次选择"
- 悬念 + 热点:"一封律师函逼出的改名,凭什么冲上 GitHub 第一?"
- 转折认知:"ChatGPT 只是中场"
- 效率承诺:"3 分钟看懂..."
- 痛点质问:"还在把 AI 当聊天工具?"

标题不超过 64 字(后台上限)。默认把最稳的一个写进文稿一级标题,其余列给用户挑。

## 产物

- 落盘 `articles/YYYYMMDD_题目_公众号文章.md`
- 首个一级标题 = 文章标题(排版环节自动只进 title)
- 交付时附:结构说明、5 个备选标题、配图建议
