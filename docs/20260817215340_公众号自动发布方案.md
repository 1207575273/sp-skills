# 微信公众号 AI 自动化发布方案

日期: 2026-08-17
状态: 方案定稿,进入测试阶段

---

## 1. 目标与业务流程

用 skill + agent 组合,实现"输入选题 -> 本地成稿 -> 发布到公众号"的半自动流水线。

```
链路一(内容生产):
  人输入选题
    -> wechat-article-writer   (写作: 搜资料 -> 撰写 -> 标题 -> 初排版)
    -> 配图环节                 (封面图 + 正文插图)
    -> dbs-wechat-html         (Markdown -> 公众号排版 HTML,15 种风格)
    -> 本地产物: 文章 HTML + 封面图 + 标题/摘要

链路二(发布):
  人确认稿件
    -> 自研 wechat-publisher skill (Playwright 操作 mp.weixin.qq.com)
    -> 存入公众号草稿箱
    -> 人工在后台点群发(终点是草稿箱,不直接群发)
```

## 2. 路线选型与决策依据

### 2.1 发布路线: Playwright 浏览器自动化(选定)

| 路线 | 结论 | 理由 |
| --- | --- | --- |
| 官方 API (draft/add + freepublish) | 弃 | 要求认证号,个人订阅号权限不够 |
| 第三方代理 API (如 wx.limyai.com 授权) | 弃 | 公众号授权给第三方服务,有安全与合规风险 |
| Playwright 操作后台 (选定) | 用 | 不受账号类型限制;代价是登录态维护 + 页面选择器脆弱性 |

Playwright 路线两个工程要点:

- 登录态: 后台 cookie 有效期只有几天。用 `storageState` 持久化,失效时提示人工扫码,做不到永久免扫码。
- 发布策略: skill 只做到存草稿,群发留给人点。规避平台风控,也留人审关口。

可抄作业的开源参考:

- LinusLing/WeChatMediaPlatformAutomation (212 star, Puppeteer): 预览/发布/声明原创,扫码登录,持续适配新版后台。选择器与发布流程直接可参考。
- iamtornado/playwright-automation (15 star, Playwright): 多平台分发,公众号走"填编辑器 + 传图 + 存草稿",Chrome 调试模式复用登录态。架构思路与本方案一致。

### 2.2 配图路线: 代码生成为主(选定)

| 路线 | 结论 | 理由 |
| --- | --- | --- |
| 代码生成 (HTML 模板截图 / 本地图表 skill) | 主 | 零 API 成本、零版权风险,技术文配图足够 |
| AI 生图 API | 备 | 写实/插画风才需要,后续按需接入 |
| 网络找图 | 弃 | 版权风险 |

- 封面图: HTML 模板 + Playwright 截图,公众号封面尺寸 900x383 (2.35:1)。已装 `xiaohongshu-cover-generator` 作为实现参考(小红书尺寸,需改)。
- 正文插图: 架构图/图表走本地已有 skill (fireworks-tech-graph / dataviz)。

## 4. 自研部分(2026-08-17 落地,2026-08-19 合并为单一 skill)

最终形态:**单一 skill `wechat-post`** 覆盖全流程,自包含、可移植:

- 写稿规范 references/writing-guide.md
- 配图模板 templates/ + 截图脚本 scripts/shoot-figures.mjs

- 状态目录(不入库):.profile/ 登录态、publish-logs/ 过程截图

首篇文章已实发。第三方 wechat-article-writer / dbs-wechat-html 的可取之处已吸收进自持规范并卸载,不再有外部 skill 依赖。

## 5. 测试计划

1. 跑通 wechat-article-writer: 给一个选题,验证成稿质量与文风适配 -> 验证: 本地生成一篇可读的 Markdown 文章。
2. 跑通 dbs-wechat-html: 用上一步产物转 HTML -> 验证: 浏览器预览排版正常,手工粘贴到公众号后台不丢样式。
3. 封面图: 先用 xiaohongshu-cover-generator 生成一张,评估改造成本 -> 验证: 产出图片文件。
4. 手工闭环: 前三步产物人工贴进公众号后台存草稿 -> 验证: 草稿箱可见、排版正确。
5. 再启动 wechat-publisher 自研,把第 4 步自动化。

前 4 步全部人工可控,确认内容链路质量后才投入发布自动化的开发。

## 6. 风险备忘

- 公众号后台改版会使 Playwright 选择器失效,发布 skill 需按"日志先行"原则打全过程日志,便于失效时快速定位。
- 登录态几天一过期,是常态不是 bug,流程设计上接受"定期扫码"。
- 第三方 skill 以完整权限运行,已装的三个均为社区来源,使用前如涉及敏感目录需先审阅其脚本(本项目含内网凭证,注意不要让 skill 触碰 git 历史与配置)。
